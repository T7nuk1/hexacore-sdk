# Шина I2C

Вся внешняя периферия платы, кроме кнопок и пищалки, сидит на одной шине I2C
(`I2C_1`, режим мастера). Драйверы датчиков — тонкие обёртки над этими четырьмя
функциями.

## API

```c
#include "hexa_i2c.h"

hexa_status_t hexa_i2c_init(void);      /* делает hexa_board_init() */

hexa_status_t hexa_i2c_write(uint8_t addr, uint8_t reg, const uint8_t *buf, uint16_t len);
hexa_status_t hexa_i2c_read (uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);

hexa_status_t hexa_i2c_write_raw(uint8_t addr, const uint8_t *buf, uint16_t len);
hexa_status_t hexa_i2c_read_raw (uint8_t addr, uint8_t *buf, uint16_t len);

hexa_status_t hexa_i2c_ping(uint8_t addr);
int           hexa_i2c_scan(uint8_t *found);
```

**Адреса 7-битные** (0x00..0x7F). Сдвигать влево на бит, как требуют некоторые
чужие библиотеки, не нужно — HAL делает это сам. Если в даташите указан адрес
0xD0, это уже сдвинутый вариант, вам нужен 0x68.

### Регистровый доступ и голый

`hexa_i2c_read()`/`hexa_i2c_write()` реализуют обычную для датчиков модель:
сначала передаётся номер регистра, затем данные (для чтения — с повторным
стартом). Так работают MPU6050, BMP280, RV-3032, VL53L0X.

`*_raw` — без номера регистра. Нужны там, где регистровой модели нет:

- AHT20 принимает команды и отдаёт результат сплошным потоком байт;
- OLED получает килобайтный кадр одной посылкой.

### Ограничение на запись

`hexa_i2c_write()` собирает `reg + данные` во временный буфер на 32 байта,
поэтому **`len > 31` возвращает `HEXA_ERR_PARAM`** и до шины дело не доходит.
Для больших посылок — `hexa_i2c_write_raw()`, где буфер ваш.

### Таймаут

`HEXA_I2C_TIMEOUT_MS` из `hexa_board.h` — 100 мс на транзакцию. При зависшей
шине каждый вызов будет стоить эти 100 мс: цикл опроса из пяти датчиков
превратится в полсекунды тишины. Если приложение начало «тормозить» —
проверьте коды возврата, скорее всего вы игнорируете `HEXA_ERR_TIMEOUT`.

### Потокобезопасность

Под FreeRTOS каждая функция берёт мьютекс шины, так что дёргать датчики из
разных задач безопасно. Мьютекс создаётся в `hexa_i2c_init()`, то есть внутри
`hexa_board_init()` — вызывайте её до старта задач, работающих с шиной.

В bare metal блокировки компилируются в пустоту. Отсюда правило: **не трогайте
I2C из обработчика прерывания**, если основной код тоже с ней работает.

Мьютекс не рекурсивный и охватывает одну транзакцию. Последовательность
«прочитать регистр — изменить — записать» из двух задач одновременно всё ещё
может перемешаться; если такое возможно, синхронизируйте на уровне приложения.

## Адреса на плате

Из `board/hexa_board.h`:

| Адрес | Устройство | Макрос |
|---|---|---|
| 0x29 | VL53L0X | `HEXA_VL53L0X_ADDR` |
| 0x38 | AHT20 | `HEXA_AHT20_ADDR` |
| 0x3C | OLED SSD1306 | `HEXA_OLED_ADDR` |
| 0x51 | RV-3032-C7 | `HEXA_RV3032_ADDR` |
| 0x68 | MPU6050 | `HEXA_MPU_ADDR` |
| 0x76 | BMP280 | `HEXA_BMP280_ADDR` |

Конфликтов в этом наборе нет. Вешая свой датчик, сверьтесь с таблицей и
прогоните сканирование.

Адреса зашиты в драйверы на этапе компиляции. Если ваш модуль отвечает по
другому адресу (типичный случай — BMP280 на 0x77, когда SDO подтянут к VDD),
правится `hexa_board.h`, а не код драйвера:

```c
#define HEXA_BMP280_ADDR        0x77
```

## Сканирование

Первое, что нужно сделать, когда датчик молчит:

```c
#include "hexa_i2c.h"
#include "xprintf.h"

static void i2c_dump(void)
{
        uint8_t found[128];
        int n = hexa_i2c_scan(found);

        xprintf("i2c: %d device(s)\n", n);
        for (uint8_t a = 0; a < 128; a++)
                if (found[a])
                        xprintf("  0x%02x\n", a);
}
```

Массив `found` обязан быть на 128 байт — функция заполняет его целиком.
Возвращается количество откликнувшихся.

Как это работает: по каждому из 128 адресов делается попытка чтения одного
байта с таймаутом 5 мс. Отсюда два следствия:

- полный проход занимает до ~0.6 с на пустой шине;
- устройства, которые не переживают чтение без предварительной команды, могут
  вести себя странно после сканирования. Диагностику стоит делать до
  инициализации датчиков, а не в рабочем цикле.

Для проверки одного адреса дешевле `hexa_i2c_ping()` — это транзакция нулевой
длины, только адресная фаза.

## Разбор ошибок

`hexa_status_t` из `hexa_types.h`:

| Код | Что произошло | Куда смотреть |
|---|---|---|
| `HEXA_OK` | всё хорошо | — |
| `HEXA_ERR_NACK` | адрес никто не подтвердил | не тот адрес, устройство не запитано, оборван провод |
| `HEXA_ERR_TIMEOUT` | ответа не дождались | шина висит в низком уровне, нет подтяжек, слишком длинные провода |
| `HEXA_ERR_BUS` | сбой контроллера или периферии | не вызван `hexa_board_init()`, конфликт адресов |
| `HEXA_ERR_PARAM` | неверный аргумент | `len > 31`, `NULL` там, где нужен указатель |
| `HEXA_ERR` | устройство ответило, но не тем | не тот чип по адресу, не прошла инициализация |

Проверять почти всегда достаточно `!= HEXA_OK`; различать коды имеет смысл
только в диагностике.

### Порядок разбора, когда датчик не отвечает

1. **`hexa_board_init()` вызвана?** Без неё контроллер I2C не настроен, а
   `xprintf` не выводит — легко решить, что «плата не запускается».
2. **Сканирование видит устройство?** Нет — проблема физическая: питание,
   провода, подтяжки, адрес. Дальше в код лезть бессмысленно.
3. **Адрес виден, но не тот.** Сверьтесь с таблицей и с перемычками на модуле.
4. **Адрес верный, `whoami` возвращает не то.** У MPU6050 ожидается 0x68,
   у BMP280 — 0x58, у VL53L0X — 0xEE. Другое значение — на шине не тот чип
   или помехи; проверьте длину проводов и скорость.
5. **`whoami` в порядке, `init` возвращает ошибку.** Тогда это уже логика
   драйвера — см. [06-sensors.md](06-sensors.md).

Функции `whoami` можно звать **до** `init` — этим и отличается «датчика нет»
от «датчик не настроился».

### Мелочи, которые стоят часа отладки

- На шине должны быть подтяжки к питанию. На готовых модулях (GY-530,
  GY-BMP280+AHT20, дисплей) они обычно распаяны; при нескольких модулях
  одновременно суммарное сопротивление падает и фронты портятся.
- Общая земля с модулями обязательна.
- Тайминги шины заданы в `hexa_i2c_init()` и дают стандартный режим (порядка
  100 кГц). Менять — правкой `drivers/src/hexa_i2c.c`; на длинных проводах
  имеет смысл замедлить, а не ускорить.

      найденные адреса. Сверить их с таблицей выше.
- [ ] Прочитать `hexa_mpu_whoami()` и убедиться, что он даёт 0x68.

### Уровень 2 — изменить

- [ ] Отключить датчик от платы и запустить сканирование снова. Записать,
      какой код ошибки возвращают функции обращения к нему.
- [ ] Написать функцию, которая по коду `hexa_status_t` печатает человеческое
      название ошибки, и использовать её вместо голых цифр.
- [ ] Прочитать регистр `WHO_AM_I` MPU6050 напрямую через `hexa_i2c_read()`,
      без драйвера. Найти номер регистра в `drivers/src/hexa_mpu.c`.

### Уровень 3 — сделать своё

- [ ] Написать свой мини-драйвер любого датчика, которого нет в SDK, по его
      даташиту. Оформить как `hexa_*.h` + `hexa_*.c` в стиле остальных:
      `init`, проверка идентификатора, чтение значения.
- [ ] Сделать монитор шины: раз в секунду опрашивать все известные адреса
      через `hexa_i2c_ping()` и печатать, какие устройства пропали или
      появились.
